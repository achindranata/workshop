01 · ReadMe

Instructions for Cowork

This file is the reference for four skills. Its deck shell — cover, navigation, sections, closing and theme — is the reference for the html-deck skill. Its three working samples are the references for the diagram skill, the interactive diagram skill and the click-through demo skill. Read this ReadMe first, then the part of the file for the skill you are creating.

Create the four skills independently

Each skill gets its own folder, its own instruction file and its own template, built only from its own part of this file. Once created, a skill must not load, call or depend on another of the four skills, on shared files or on this file. Where two skills need the same thing — a logo, a color, a CSS rule, the slide frame — copy it into each skill.

The samples are references, not content

The interactive diagram skill and the click-through demo skill serve any use case the user prompts for. The Copilot data flow (Section 03) and the Cowork production review (Section 04) only show the pattern: layout, styling, interaction and output rules. Take the rules from them; take the subject, content, data and language from the user's prompt each time the skill is used.

How to create each skill

Steps 1–6 are for the diagram, interactive diagram and click-through demo skills. The html-deck skill keeps the shell and drops the samples — follow slides 1.5–1.7 for it.

  1. Isolate the sample. Open this file's source and take only what the skill's section uses: its markup, the CSS rules it needs and its script. Leave out the deck shell — navigation, cover, closing, slide headers and footers, this ReadMe — and everything the other sections use.
  2. Turn the sample into the skill's template. Keep the structure, class names, sizes, colors and behavior. Replace the content with [placeholders]; the sample's subject is not part of the skill. Keep the Microsoft logo; the customer slots are [Customer Name] and [Customer Logo].
  3. Write SKILL.md. When to use it and when not to, the workflow, the output rules on the next slides, guardrails and one worked example. For the interactive diagram and click-through demo skills, the workflow starts from the user's use case.
  4. Add the checks the skill needs — for example a layout check and a self-contained check — inside the skill's own folder.
  5. Test it on a new subject and confirm it matches the sample's look and behavior without this file.
  6. Keep them separate. Create, test and report each skill on its own; never merge them or make one call another.

Rules every skill carries (each in its own copy)

  • Self-contained: one HTML file; inline CSS, and inline script only where the skill uses it; images as data URIs; no web fonts, external stylesheets or libraries.
  • Flat layout: no per-page, per-section or per-slide rounded cards. Rounded corners only on boxes, sub-cells, pills, table cells and call-outs.
  • Color = category: one palette used the same way across boxes, wires, legend, steps and pop-ups.
  • Grounded content: never invent products, capabilities, flows or numbers; cite Microsoft Learn sources; mark anything unconfirmed "verify". Demo data is illustrative and labeled that way.
  • Branding: the Microsoft logo stays; the customer appears only as [Customer Name] and [Customer Logo] until real values are given.

01 · ReadMe · HTML deck skill

HTML deck skill — output rules for instruction.md

Start
Every deck starts from a copy of html-deck-template.html — never from scratch. Content comes from the user's prompt, files and sources; the template supplies only structure and design.
Structure
Cover, then sections of slides, then Thank You. Add or remove sections and slides as the content needs, but keep the order and the slide markup the template uses.
Navigation
Ids slide-1 to slide-N with no gaps; one tab per section with its first and last slide; one chip per slide in the single, always-visible chip row; footer numbers section.slide; the slide counter shows the real total. Recount after every change.
Slides
Each slide is 1280 × 720 and scales to the window; content fits without scrolling — split a slide rather than shrink text. Present mode, ← / → and Esc keep working.
Design
Use the template's theme as saved in the skill: fonts, colors, title style, cover and closing, footer brandmark. Flat layout — no rounded cards around a whole slide, page or section; rounded corners only on table and call-out cells.
Content
Never invent names, numbers, URLs or quotes; anything not given stays a [ ] placeholder. US English unless the user asks otherwise. No editorial or change notes in the HTML.
Delivery
One self-contained HTML file: inline CSS and script, images as data URIs, no external fonts or libraries. Check the slide, chip and tab counts before delivering.

HTML deck skill — customize the template, then resave

Put these steps in instruction.md so the user can rebrand the template at any time. Slide 1.7.1 shows it as a click-through.

  1. The user uploads their brand: their own logo (PNG or SVG) and a reference design — a PowerPoint template, a sample deck, a PDF, a screenshot or a brand guide.
  2. Read the reference design: fonts, text and background colors, title size, weight and tracking, margins, cell style, cover and closing layout, footer and logo placement.
  3. Restyle a copy of html-deck-template.html — design only. The structure stays: 8 slides, tabs, chips, ids, footer numbering and scripts. The logo goes in as a data URI where the Copilot wordmark and brandmark sit today.
  4. Show the result — cover, one content slide and the closing — and adjust until the user says they're happy with it.
  5. Resave the html-deck skill only when the user asks: replace html-deck-template.html in the skill with the customized version and update the design section of instruction.md to describe the new theme and logo.

What changes, what stays

  • Changes: logo, wordmark, fonts, colors, cover and closing backgrounds, title style, cell fills, footer brandmark.
  • Stays: slide size, slide markup, navigation, present mode, keyboard controls, placeholders and the output rules on slide 1.6.

Until it is resaved, the installed skill keeps its current design. Every deck made after the resave uses the user's branding.

01 · ReadMe · Diagram skill

Diagram skill — output rules from Section 02

Page
Flat header (kicker, claim-style headline, lede), then one flat section per diagram: caption and gray sub-caption, a horizontally scrollable frame holding the canvas, in-frame legend, footnote and status line, then a numbered walkthrough and an optional note call-out. End with the icon credit.
Drawing
Boxes are absolutely positioned divs on a fixed canvas (about 1,400 px wide at most). Zones are dashed boundaries; a later or optional path sits in a dashed ghost zone. Elbow wires are drawn with CSS borders, arrowheads with CSS triangles. Each wire has a label pill "N · 1–3 words"; later paths are numbered G, G1, G2 and drawn dashed.
Boxes
Logo, bold title, one or two gray meta lines, optional sub-cells (key word + text, tagged chips such as script / model) and a footer line for status or an explicit "not" statement. Active-path boxes are tinted; others stay white. Text never below 13 px.
Palette
Source / data blue #2558C6 · User purple #7A4FD1 · Service green #0f7b6c · Processing slate, dashed border · Output gold #b9770a. A wire takes the color of the box it starts from.
Embedding
Every class is prefixed dg- and every variable --dg-, set on the wrapper, so the diagram drops into any host page without clashes.
Limits
No JavaScript, no canvas, no SVG files. Logos are written as logo:<key> and swapped for data URIs before delivery. In this file each diagram is split across slides only for display — in the template, keep each diagram's caption, frame, walkthrough and note together in one .dg-sec.

01 · ReadMe · Interactive diagram skill

Interactive diagram skill — any use case, one pattern

Use cases come from the user. Any structure or flow: a solution architecture, a data flow, a request lifecycle, security or compliance layers, a governance or operating model, an integration, a licensing path. The Copilot data flow in Section 03 is only the reference for how the output looks and behaves.

From the user's prompt

The subject and claim · the parts (boxes), boundaries (zones) and steps (wires) · the category names · every pop-up's text · the sources · the language · the customer, if any.

Output rules — apply to every use case
1 · Slide frame
One 1280 × 720 slide in the Copilot Presentation Template look used by this file, copied into the skill: white canvas, small uppercase eyebrow, claim-style title in Segoe Sans Display (regular weight, tight tracking); the diagram block scaled to fit below; footer with section number and the Microsoft + Copilot brandmark, plus [Customer Logo] when a customer is involved. A linked Sources line sits under the diagram.
2 · Top row
A hint pill with a pulsing dot that says what to click, and an inline legend of the categories and line styles actually used.
3 · Canvas
A fixed canvas (1184 × 510 in the sample). Zones mark boundaries: tinted for a sub-boundary, dashed gray for anything outside it. Boxes have a title, a short meta line, optional sub-cells and an optional footer for a status or "not" statement. If text doesn't fit, split into a second slide rather than shrink it.
4 · Categories
Three to five, relabeled to fit the use case. Each keeps one color everywhere — box top border, wire, pill, legend, pop-up top border. Sample palette: blue #2e8ccc, green #4f7a0a, navy #0b3d6e, purple #7a4fc2, red #d81e1e for warnings.
1.9Install · ReadMeMicrosoftCopilot
01 · ReadMe · Interactive diagram skill

Interactive diagram skill — output rules, continued

5 · States
Boxes on the main path are tinted; optional or off-by-default boxes are dashed; everything else stays white.
6 · Wires
Right-angle paths with arrowheads pointing the way things flow, colored by the category they start from. Main path solid and numbered 1 → N in order; alternate or optional paths dashed with a moving flow and numbered G1, G2 and so on. Each pill: number + one to three words.
7 · Click anything
Every box, sub-cell, zone and numbered pill opens a pop-up: kicker (type · step), title, meta line, one paragraph, two to four bullets, one to three source links, Previous / Next with "n / total". Order: numbered steps first, then boxes, then zones.
8 · Controls
← / → step through pop-ups, Esc or a click outside closes, focus returns to the clicked item. While a pop-up is open it takes the arrow keys and Esc, so they don't move the slides. Clickable items are buttons or carry role="button", tabindex and Enter / Space support.
9 · Reading guide
One line under the canvas on how to read it (e.g. "Follow wires 1 → 6; the dashed G-path replaces steps 3–4"), plus a pointer to notes kept inside the pop-ups.
10 · Content
Every pop-up statement is grounded in a source; Microsoft product facts link to Microsoft Learn; anything unconfirmed is marked "verify". Reuse nothing from the sample unless the user's use case is the same subject.

Click-through demo skill — any product, any task

Use cases come from the user. Any product, agent or app doing any task: Cowork producing a report, Copilot Chat answering from files, a Teams meeting recap, an Outlook triage, a custom agent handling a request, a business app flow. The Cowork production review in Section 04 is only the reference for how the output looks and behaves.

From the user's prompt

The product to mock up · the customer and their task · the prompt, the responses and the steps · the files and data it uses · the result it produces · the language of the mock-up · the requirements to call out.

Output rules — apply to every use case
1 · Slide frame
The same 1280 × 720 Copilot-theme slide frame as the interactive diagram — copied into this skill, not shared. Footer brandmark: [Customer Logo], Microsoft and Copilot; the customer is named [Customer Name] until given.
2 · Two columns
A story column on the left (about 400 px) and the product mock-up filling the rest.
3 · Story column
A gradient hero block with the product icon, name, license or requirement pills and one line of value; three colored strips (in the sample: Reaches for, Trades, Gives you back — relabel to the product); a red call-out for prerequisites or access; a use-case box "[Customer Name] use case · one-click demo".
4 · Mock-up
A faithful replica of the named product's interface — its navigation, main pane and side or detail pane. It opens idle, with the starting control highlighted and a "click to start" hint pill.

01 · ReadMe · Click-through demo skill

Click-through demo skill — output rules, continued

5 · The run
One click plays a timed script: the user's input, then the product's responses at set delays; a progress list of four to seven steps, each going pending → working → done; produced files and references appearing in their lists as they are made. The whole run finishes in about 6–10 seconds.
6 · Approval
Anything that would send, post, change or delete stops at an approval gate (Approve / Review first) and only completes when clicked.
7 · Result
At least one produced output opens in an overlay window mock (title or address bar, close button) and is itself interactive — filters, charts with tooltips, a table, a document or message preview — driven by one data object.
8 · Controls
Reset clears every timer and restores the idle state; Esc or a click outside closes the overlay; printing shows the finished run.
9 · Content
All data is illustrative and labeled — a tag in the result ("illustrative data · created by …") and the caption "Illustrative mock-up … for demonstration only". Names of people, sites and assets are anonymized; no real customer data. Product behavior shown in the run is grounded, with Microsoft Learn sources under the mock-up. Reuse nothing from the sample unless the user's use case is the same.

Done when: each of the four skills exists on its own, carries its own template and checks, and can reproduce its reference's look and behavior on a new subject without this file or the other three skills.
